## **<span style="color:#1ED2C8;">프롬프트 작성 요령 및 준수 사항</span>**
1. 구현할 아트워크의 캔버스 크기, 오브젝트, 색, 움직임, 인터랙션 등을 정리하고 지시할 것.
2. 사용할 알고리즘 물감(로직)을 디테일하게 정의하고 올바른 용어를 사용해서 지시할 것.
3. 지시 순서는 캔버스 설정 > 오브젝트 묘사 > 애니메이션 >  인터랙션 설명 순으로 할 것.
4. 마음에 들지 않는 결과가 계속 반복된다면 새로운 채팅 창이나 다른 LLM에서 새로 시작할 것. 
5. 수정 요청 시 전체를 바꾸어버리는 경우가 있으므로 부분만 수정 요청하거나, 수정하면 안되는 영역을 설정할 것.
6. AI가 짠 코드에는 오류가 있을 수 있으므로 필요시 다른 LLM을 이용하여 refactoring을 요청할 것.
7. 설명 주석을 요청하여 사용한 로직, 알고리즘과 함수의 의미를 파악할 것. 
8. AI가 짜 준 아트워크에 만족하지 말고, 내 입맛에 맞게 변수의 값을 바꾸어 볼 것.
9. 참고할 이미지를 업로드할 때는 어느 부분을 참고해서 만들지, 개선할지 등을 자세히 지시할 것. (첨부 용량 주의)
10. 다른 사람이 만든 코드를 활용할 때에는 AI에게 코드의 로직을 물어보고 파악한 후 필요한 부분만 사용할 것. (저작권 여부 확인)

## **<span style="color:#f49571;">예시 프롬프트 1</span>**

<기본 사항>
- 캔버스 크기: 1000 x 1000 픽셀
- 배경: 검은색
- 선 또는 리본: 흰색 계열
- 잔상이 남으며 서서히 사라지는 generative motion 사용

<br>

<표현하려는 심상>
- 마음 속에서 수많은 생각이 흐르는 모습을 추상적으로 표현한다.
- 생각은 단순한 직선 흐름이 아니라 바다 속 조류처럼 복잡한 흐름을 가진다.
- 생각은 무의식에서 떠올라 위쪽으로 흘러가는 구조로 표현한다.

<br>

<구현해야 하는 generative 시스템>
1. Particle System
각 particle은 **하나의 생각(thought)**을 의미한다.
많은 수의 particle이 동시에 존재한다.
particle은 아래에서 생성되어 위로 이동한다.
화면 위쪽을 벗어나면 삭제되고 새로운 particle이 아래에서 생성된다.
2. Ocean Current
전체 공간에는 큰 규모의 흐름(ocean current) 이 존재한다.
이 흐름은 느린 noise 기반 벡터 필드로 구현한다.
particle의 전체적인 이동 방향을 결정한다.
3. Flow Field
ocean current보다 더 세밀한 local flow field를 추가한다.
Perlin noise를 사용하여 공간의 각 위치에 방향을 부여한다.
particle은 이 흐름을 따라 자연스럽게 움직인다.
4. Emotional Vortex
화면 내부에 몇 개의 vortex(소용돌이) 를 생성한다.
particle이 vortex 근처에 오면 회전하며 휘어지는 움직임을 만든다.
이는 감정이나 기억에 의해 생각이 휘어지는 현상을 표현한다.
5. Depth Layers
각 particle은 depth 값을 가진다.
depth에 따라 선 두께와 투명도가 달라진다
깊은 생각은 굵고 밝게, 먼 생각은 얇고 흐리게 표현한다.
6. Ribbon Geometry
particle의 이동 궤적을 단순한 선이 아니라 리본 형태의 곡면(ribbon) 으로 표현한다.
particle이 지나간 위치를 history 배열에 저장한다.
이동 방향의 수직 벡터(normal vector) 를 계산하여 리본의 좌우 폭을 만든다.
좌측 점들과 우측 점들을 연결하여 하나의 리본 shape을 그린다.
7. Ink Brush Texture
리본의 두께를 일정하게 하지 말고
noise 기반 변형을 추가하여 먹 브러시 같은 질감을 만든다.
8. 조절 가능한 전역 변수를 코드 상단에 배치
